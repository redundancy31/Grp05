# Known limitations and evidence gaps

- The C-first migration is partial. Native `make` build/test/verify/signals/readiness recipes and local C tests exist, but GNU Make was unavailable here and the recipes were only validated through direct GCC equivalents plus static review.
- Native C now provides the registered version/dataset config used by the benchmark runner, a reusable statistics module, five-repeat benchmark collection with semantic correctness gates and raw/summary evidence, streaming rival replay capture/accounting/sweep with graph generation, perf CSV normalization with a Linux `perf stat` entry point, and GCC assembly generation/heuristic annotation targets. These additions are not yet an end-to-end replacement for every legacy output format. Race orchestration/state remains Python-owned; native verification/plotting/replay do not yet all consume the shared config; optional Python comparison has not been extracted from `scripts/project.py`. The compulsory project as a whole is therefore not yet Python-independent.
- The native C test suite covers parser contracts, an independent synthetic indicator/crossover/bar case, replay support tests, portable kernel correctness, official test20 summary plus trace checks, statistics edge cases, dataset/config aliases, perf CSV normalization, and rival sweep/evidence/error fixtures. Fixed-point overflow, all allocation failure branches, full stress, and prior Python workflow coverage have not all been ported.
- The native signal generator was run on the supplied development file and produced fresh `.dat`, GNUplot script, and nonempty PNG under `build/native/`. Existing `plots/` evidence remains unchanged.
- Native benchmark smoke validation used only the supplied test20 file on Windows; it is software-path validation, not controlled performance evidence. Existing `results/laptop/` data remains legacy evidence for its original source/flags.
- Stage 0 was corrected and directly validated at all four optimization levels for compilation and O2 for runtime. The local O2 assembly optimized away the named recursive function; no recursive-machine-code or speed-difference claim is made. There is no controlled Stage 0 timing set or physical LED evidence.
- The current workstation has GCC 16.2.0 but no Make executable in PATH or the checked MSYS2 UCRT64/MSYS/Git locations. GNU Make recipes were not executed. Use MSYS2 UCRT64 or Linux with Make for recipe-level validation.
- The final coursework PDF is present, but no installed local text extractor was found. Existing page citations still need verification against that final PDF; no quotations or new page references were invented.
- The authoritative coursework PDF is present at `provided/CSC1103-1104_Mini_Project_2026-27_Tick-to-Trade_final.pdf`. The requirements matrix and report map use it as the assignment source.
- Local laptop stress benchmark evidence exists under `results/laptop/`. It supports laptop-specific observations only; it is not evidence of Pi performance.
- The local `results/pi/` tree contains only `README.md`. Pi benchmark, perf, replay, LED, race, compiler assembly, and native AArch64 kernel results are therefore **PI EVIDENCE REQUIRED / NOT LOCALLY VERIFIED** in this audit.
- The handoff target describes Raspberry Pi 5, AArch64, GCC 14.2.0, performance governor, and taskset CPU 3 for controlled collection. Verify the actual device, compiler, governor, and applied affinity in each Pi run manifest before reporting them as measured conditions.
- Windows x1000 replay files and Windows portable-kernel fallback results do not establish Pi replay behavior or native AArch64 assembly execution.
- NumPy comparison is batch/offline processing; its timing is not timestamp-paced replay latency. No parser, storage layout, C/Python engine, or scalar assembly implementation is presumed to win.
- The root-level zero-byte `signals.png` is suspicious because `plots/signals.png` is the canonical plot. It was not removed. See the evidence inventory for a safe manual removal command that first checks the canonical file.
- Report, presentation/demo videos, signed declarations, separate peer evaluation, and completed signed prediction logbook entries remain team deliverables.
