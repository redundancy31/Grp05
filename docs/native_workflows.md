# Current native workflows

Use the repository root as the working directory. On Windows use MSYS2 UCRT64 with GCC, GNU Make, and GNUplot; on Linux/Pi use GCC, GNU Make, and GNUplot. This Windows workstation lacks GNU Make, so the recipes below have not been executed here. Native output examples use a fresh directory below `build/native/`; never reuse an existing evidence directory. The supplied Group 05 datasets and official expected-answer file must be present at their supplied names. The expected-answer file is an input, never generated by the implementation.

## Core C workflow

```sh
make
make test
make verify
make replay-test
make asm-test
make signals
make readiness
```

The aliases `test20`, `dev`, and `stress` are currently resolved by the native benchmark configuration module. Existing engine, verification, signals, and replay CLIs still accept explicit data paths; they do not all use that module yet. Windows paths with spaces should be quoted in MSYS shell commands.

## Benchmark

```sh
make benchmark DATASET=test20 VERSION_ID=all REPEATS=5
make benchmark DATASET='test20 - Copy (6).csv' VERSION_ID=v5_manual_digit_parser_running_double_stream_O2 REPEATS=5 SHORT_WINDOW=3 LONG_WINDOW=5
```

`VERSION_ID` accepts a registered v0-v10 ID or `all`; `REPEATS` must be at least five. Outputs use the selected `BUILD_DIR` and a unique monotonic timestamp directory under `benchmark-results/`. Existing binaries must be built from the current Makefile; the runner compares summary results before timing and rejects nonzero exit, incomplete phase output, or changed results.

## Rival capture, sweep, and graph

```sh
make rival DATASET='test20 - Copy (6).csv' RIVAL_BASELINE=v0_baseline_strtok_running_double_heap_O0 RIVAL_FAST=v5_manual_digit_parser_running_double_stream_O2 RIVAL_SPEED=1000 RIVAL_LIMIT=20 RIVAL_SHORT=3 RIVAL_LONG=5 RIVAL_OUTPUT_DIR='build/native/rival-20261106-153000'
```

The output directory's parent must exist and the output directory must be new. The target captures both native replay runs, validates matching trade order and effective signals, computes bounded-memory position/P&L state and the reaction sweep, then generates a PNG from fresh GNUplot data/script. Compact summaries are the default; pass `RIVAL_DETAILS=1` to retain per-decision detail CSVs. Set `RIVAL_LIMIT=` to process the dataset through EOF. This is offline replay analysis, not live race orchestration.

## Perf

On Linux only, use a fresh directory and select one explicit version. This command is not available on Windows:

```sh
make profile PROFILE_VERSION=v1_baseline_strtok_running_double_heap_O2 DATASET='test20 - Copy (6).csv' SHORT_WINDOW=3 LONG_WINDOW=5 PROFILE_DIR='build/native/profile-20261106-153000'
```

It preserves raw `perf stat -x,` output and writes normalized counters/IPC plus parser notes. It does not change affinity or the CPU governor. To normalize an already existing raw file without collecting counters:

```sh
make perf-summary PERF_RAW='path/to/perf.raw.csv' PERF_SUMMARY='build/native/perf-summary.csv'
```

Summary output paths must be fresh. Unsupported counters and missing IPC remain `NA`; user/kernel suffixes are retained in the scope column.

## Compiler assembly

```sh
make assembly ASSEMBLY_DIR='build/native/assembly-host-20261106-153000'
make annotate-assembly ASSEMBLY_PATH='build/native/assembly-host-20261106-153000/replay_engine.s' ANNOTATION_PATH='build/native/assembly-host-20261106-153000/annotation.md'
```

The generated `.s` and manifest are host-specific. The annotation is a heuristic, separate file and refuses to overwrite an existing output. A host listing does not count as Pi/AArch64 evidence. Review the function/loop labels and instructions against the source and target ISA manually.

## Validation boundary

These local commands do not replace Pi validation. On the Pi, repeat `make`, `make test`, `make verify`, `make signals`, and `make readiness`; run a bounded replay/rival smoke first. Only separately authorized runs should start the required ten-minute 1x replay or full-stress 100x/1000x experiments. Live race P&L is not implemented as a native workflow yet.
