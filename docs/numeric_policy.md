# Numeric policy

## Market engines

- The authored price and quantity parser maps buyer-maker `False` to `is_buy=1`; `True` maps to sell.
- VWAP is the ordered cumulative `sum(price * quantity) / sum(quantity)` in `double`. A row with non-positive quantity is rejected by the current parser contract.
- SMA windows use the supplied Group 05 settings: test20 3/5, development and stress 30/60. Each SMA is absent until its entire window is available. The first possible crossover is after two consecutive rows with both SMAs, at `long_window + 1`.
- Signals use signed crossover transitions: previous difference `<= 0` and current `> 0` is BUY; previous `>= 0` and current `< 0` is SELL. Equality alone is not a signal.
- One-second OHLC grouping uses integer timestamp microseconds divided by 1,000,000. The final active bar is emitted at EOF.
- Variant v6 uses checked signed `int64_t` price units at scale `10^8` for SMA/OHLC. VWAP remains double. The existing double shadow in v6 and the naive variants is a comparison/check policy; it must not be used to claim fixed-point output without examining the primary path and signal policy.
- v9 exact AoS and v10 exact SoA perform count/load passes. Their source files and timing scopes are measurement inputs; changes require new applicable measurements.

## Stage 0

- The closed-form `n(n+1)/2` check divides one even factor before multiplication and checks the remaining product against `UINT64_MAX`. Iterative sum runs only when the checked mathematical result fits.
- CLI unsigned inputs accept decimal digits only. Negative signs, malformed values, zero repeat count, excessive repeat counts, and overflowing sums are rejected with nonzero status.
- Recursive verification is capped at N=20,000 for stack safety; the default arithmetic experiment is N=100,000,000. The separate calibration compares repeated N=10,000 and N=10,001 inputs in batches, checks both results, and reports median time per sum.
- The compiler may transform recursive source. On the local GCC 16.2.0 `-O2` listing, a `sum_recursive` symbol/call was absent after optimization. The measured output does not claim a guaranteed recursive machine-code path or a guaranteed speed difference.
- Stage 0 uses `provided/timing.h` and `provided/led.h`. Host fallback LED text is not physical hardware evidence.

## Independent verification tolerance

The official answer is the supplied `test20_expected - Copy (6).txt`, not output generated by an engine. Native tests parse its final VWAP, signal counts, and OHLC row count; the ladder verification checks the published trace values at BUY trade 7 and SELL trade 10 and all three published OHLC bars. The independent synthetic fixture separately checks crossover and EOF bar behavior. Full row-by-row comparison of every test20 SMA/VWAP value is not yet ported. Floating output is formatted to eight decimal places by the market engines; the native unit test uses a `1e-8` summary tolerance. No floating tolerance applies to signal ordinal/type or integer trade/bar counts.
